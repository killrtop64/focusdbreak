## Нативная проверка Windows: ограничение среды

Выполнена попытка запуска packaged exe через Playwright Electron с отдельной тестовой папкой userData.

Процесс начал запуск, но остановился в Electron install_dir_access.cc:

> Sandboxed processes cannot read ... release/win-unpacked: its ACL has an entry for an AppContainer package SID but none for ALL APPLICATION PACKAGES.

В логе также есть ошибка Windows os_crypt. Это не ошибка доменного таймера и не доказательство несовместимости Electron с обычной Windows. Среда не позволила закончить нативный smoke-test.

Не проверены: окно приложения после загрузки, native storage после перезапуска, трей, pin/compact, фактическая доставка Windows-уведомлений, автозапуск, установка, удаление и обновление.

Решение для проверки: обычная Windows-папка и пользовательская сессия либо соответствующий Windows runner / VM. Отключение sandbox и изменение системных ACL для обхода ограничений в рамках аудита не выполнялись.

## Находки, требующие исправления

### P0. Данные могут быть потеряны при восстановлении и ошибках

**1. Молчаливое обрезание данных.**

src/core.js: restoreState ограничивает задачи 100 записями, history и completedTasks — 2000, заметки — 90 датами. Параметры задач и тексты также нормализуются с обрезанием. Пользователь не получает отчёт о потерянных записях.

Текущий тест прямо подтверждает обрезание 150 задач до 100; по новому ТЗ это больше не допустимая политика импорта.

Исправление: раздельные валидация / миграция / применение, предварительный отчёт и безопасный отказ вместо скрытого удаления.

**2. Повреждение и неизвестная версия превращаются в пустое состояние.**

В src/app.js ошибка JSON.parse оставляет initial пустым. src/core.js возвращает createState для неизвестной версии. desktop/main.cjs возвращает null при ошибках чтения. Следующее сохранение может записать пустое или нормализованное состояние поверх исходного файла.

Нет последней исправной копии, журнала миграций и recovery UI. Это установлено по коду; нативный сценарий отказа диска ещё не воспроизведён.

Исправление: различать отсутствие файла, повреждение, несовместимую схему и I/O error; сохранять исходник; не включать запись, пока не принято безопасное решение восстановления.

**3. Удаление необратимо.**

Обработчики удаления и очистки выполненных в src/app.js окончательно фильтруют задачи из массива. Журнал completedTasks хранит только id и дату, а не восстанавливаемую задачу.

Исправление: корзина / tombstone и отмена; импорт JSON не является заменой восстановления отдельной задачи.

**4. Отложенное сохранение заметки.**

Заметка записывается через таймер 350 мс. Native before-quit ждёт только уже полученные main-process записи и не запрашивает сброс незавершённой renderer-операции.

Риск потери последних символов при быстром закрытии требует отдельного lifecycle-теста и исправления.

### P1. Упаковка и воспроизводимость

**5. Метаданные и инструкции не согласованы.**

- package.json: 2.0.0; package-lock.json и его корневая запись: 1.0.0.
- Android versionName: 1.0, versionCode: 1.
- README и CONTRIBUTING описывают старый buildless-сайт и прежние пути dist/core.js.
- start-focus-break.cmd по-прежнему запускает HTTP preview, а не Electron.

**6. CI не соответствует новой структуре.**

Checks не выполняет npm run build перед browser tests. dist отслеживается Git, а src, desktop и Android пока имеют незакоммиченные / untracked файлы. Без сборки CI может тестировать не тот интерфейс. Нативных Windows/Android jobs нет.

Следует выбрать и документировать политику generated dist, но не удалять его наугад: предыдущая схема публикации использовала эту директорию.

**7. Portable не переносит данные.**

electron-builder создал self-extracting Portable exe, но desktop/main.cjs всегда использует app.getPath('userData'), кроме тестового FOCUS_BREAK_DATA_DIR.

PORTABLE_EXECUTABLE_DIR не используется. Поэтому файл без установки пока не соответствует требованию переносимого каталога данных.

### P1. Незавершённые системные функции

**8. Нет напоминаний задач.**

Есть scheduler окончания таймера, но нет расписания дедлайнов, snooze и индивидуальных настроек задачи. Это отсутствие функции, а не только нехватка теста.

**9. Ошибки платформенной интеграции скрываются.**

syncNative вызывается с пустым catch. При отказе уведомлений понятного устойчивого состояния нет; уведомление об отказе разрешения может быть немедленно заменено сообщением «Настройки сохранены».

**10. Компактный режим не полностью выключается.**

zen-exit вызывает только setZen(false). Он не снимает body.compact, не вызывает setCompact(false) и не восстанавливает размеры / always-on-top. Найдено по статическому анализу; нативная проверка не завершилась из-за ACL.

**11. Нет глобальных hotkeys и светлой темы.**

Текущий document keydown — локальный обработчик, а не globalShortcut Electron. Тёмное оформление единственное. CPU/RAM в фоне не измерены; heartbeat 250 мс и отключённый background throttling требуют проверки.

### P1. Повторение и модель

Следующая задача создаётся только после завершения предыдущей. Пропуски не восстанавливаются в историю, стратегия для смены зоны не определена. При 100 задачах новый повтор не создаётся без отдельного сообщения об этой причине.

Есть тесты выходных, конца месяца/года и дублей. Нет специальных тестов DST, смены зоны/часов и редактирования серии.

Проекты и теги — строки, а не самостоятельные сущности. Нет description, dueTime, подзадач, истории операций, revisions и deletedAt. Это допустимый прототип, но пока не расширенная модель из ТЗ.

## Реальное состояние Android

Положительное:

- Нативный Gradle-проект создан.
- App ID io.focusbreak.app и Activity присутствуют.
- Пять Capacitor-плагинов обнаруживаются при sync.
- Старый системный Java 8 не подходит compileOptions VERSION_21.
- Portable Temurin JDK 21.0.12.1 скачан, распакован и запускается.
- Начальная ошибка Capacitor CLI связана с os.userInfo в ограниченной Windows-сессии. Локальный compatibility launcher позволяет создать проект без смены стека.
- Начальный сетевой timeout загрузки JDK устранён использованием предоставленного средой proxy.

Незавершённое:

1. npm run android:apk ссылается на отсутствующий scripts/build-android.mjs. Это реальная недоделка проекта, помимо ограничений окружения.
2. Полный Android SDK не установлен; sdkmanager по ожидаемому пути отсутствует. Установка остановлена после перехода к аудиту.
3. Указан smallIcon=ic_stat_focus, которого нет в ресурсах проекта.
4. Android web assets скопированы до последней Vite-сборки; нужен повторный cap sync.
5. Версия и фирменные launcher icons не доведены.
6. Нет проверенной схемы подписи release APK.
7. Нет собранного APK и проверки на устройстве.
8. Manifest оставляет allowBackup=true. Нужно явно определить политику системного резервного копирования.

Разрешения POST_NOTIFICATIONS и SCHEDULE_EXACT_ALARM уже объявляются библиотечным manifest плагина — их отсутствие в manifest приложения само по себе не доказывает ошибку. Permission flow и merge всё равно требуют нативной проверки.

Совместимое решение: завершить JDK 21 + SDK 36, починить build entrypoint, синхронизировать ресурсы, собрать Gradle на обычной машине / CI, затем проверить APK. Electron/Capacitor менять для этого не нужно.

setup-android.mjs также требует доработки: существующий ZIP пропускается без повторной проверки hash, поэтому после прерванной загрузки возможна повторная попытка распаковать неполный файл.

Доступ к D, GitHub и обычной нативной среде проверки — необходимые условия выполнения соответствующих действий, а не основание считать их сделанными.

## Оценка и следующий шаг

Подробная калькуляция — в ROADMAP.md:

- Windows: 32–56 часов + 25% резерва = **40–70 часов**.
- Android: 20–36 часов + 25% = **25–45 часов**.
- Основной стабильный выпуск на двух платформах: **65–115 активных часов**.

Сначала отдельное изменение защиты данных; затем воспроизводимая Windows-сборка и нативная приёмка. Календарь, привычки и синхронизация не включены в эту оценку и не разрабатываются одновременно с исправлением хранения.
