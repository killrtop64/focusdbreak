# Переносимый режим Windows

В новом Portable-кандидате реализован отдельный каталог данных рядом с запускаемым EXE. Логика выбора каталога, файловое хранение и перенос проверены автоматическими тестами. Нативный прогон реального launcher остановился до интерфейса на ограничении ACL sandbox; нативная приёмка не пройдена.

Локальный файл: `release/candidate-portable/Focus-Break-2.0.0-Windows-x64-Portable.exe`, 110194512 байт, SHA-256 `49a0163030eecb5b7d0cb9e2813135731633f78d8ebf9d63a86a37a58af65b79`. Рядом находятся SHA256SUMS.txt и BUILD-INFO.json с хешами исходников. Пакет содержит текущий код переносимого режима; 24 runtime-файла сверены с app.asar. Подписи и публичного релиза нет.

## Как устроена папка

```text
Моя папка/
  Focus-Break-2.0.0-Windows-x64-Portable.exe
  Focus Break Data/
    focus-break.json
    focus-break.last-good.json
    backups/
    Chromium/
    logs/
    Crashpad/
```

Имена задач, корзина, настройки и заметки хранятся в журнале `focus-break.json`. Копии остаются в той же папке данных. Каталоги Chromium, логов и crash dumps также перенаправляются внутрь неё. Если launcher переименовать или заменить новой версией в той же папке, каталог `Focus Break Data` не изменится.

Для переноса:

1. Полностью завершите приложение через «Выход» в трее. Простое закрытие окна может только скрыть его.
2. Скопируйте **EXE и всю папку Focus Break Data вместе**.
3. Запустите EXE из нового места. Одного файла EXE недостаточно для переноса данных.

Launcher Electron Builder временно распаковывает Electron в Windows TEMP. Для этого нужно свободное место. Распакованный runtime — отдельные файлы от переносимого журнала задач; режим не обещает полного отсутствия временных файлов или системных следов Windows.

## Выбор места хранения

Приоритет задаётся до `app.ready` и захвата single-instance lock:

1. Если задан `FOCUS_BREAK_DATA_DIR`, используется этот абсолютный путь. Это явно выбранный режим, полезный для изолированных проверок; автозапуск отключён.
2. Упакованный Windows Portable использует `PORTABLE_EXECUTABLE_DIR`, который launcher устанавливает в каталог внешнего EXE. Используется подпапка `Focus Break Data`, а не временная папка распаковки.
3. Установленная / обычная версия продолжает использовать прежний `app.getPath('userData')`. Её данные и расположение автоматически не меняются.

Относительные пути, путь вида `D:folder` и путь без указанного диска отклоняются. Поддерживаются пробелы, Unicode и абсолютный UNC-путь; доступность сетевого носителя остаётся ответственностью выбранного пользователем расположения.

Перед переключением нестандартного каталога выполняется реальная пробная запись, fsync, rename и удаление собственного временного файла. Существующий журнал при этом не изменяется. Ошибка доступа, заполненный диск или файл вместо каталога останавливают запуск с сообщением на русском и английском. Автоматического перехода в Roaming или другой каталог нет.

Папка данных и режим показаны в настройках Windows-версии. Кнопка открытия передаёт в main process только действие; путь берётся из уже выбранной конфигурации и не поступает из renderer.

## Переход со старых кандидатов

Ранние Portable-файлы в `release/` и `release/candidate-trash/` использовали профиль Windows. Новый режим не копирует и не удаляет эти данные автоматически. Перед переходом экспортируйте JSON из старой версии, затем импортируйте в новой. При первом запуске нового режима без импорта будет отдельная пустая рабочая папка; прежняя база останется на прежнем месте.

Смена Portable на установленную версию также не является синхронизацией. Для переноса между ними используйте ручной экспорт / импорт. Перед откатом на старый код сохраните экспорт и каталог данных отдельно: старые версии не понимают оболочку нового журнала.

## Автозапуск

В Portable и явно выбранном каталоге автозапуск отключён в UI и main process. Стандартный механизм Electron иначе регистрировал бы путь временно распакованного приложения. Профильная упакованная Windows-версия сохраняет существующую настройку автозапуска. Portable не включает и не выключает автозапуск уже установленной копии.

## Что проверено

- Выбор режима и приоритет явного пути; установленный профиль остаётся прежним.
- Недопустимые пути, права записи, заполненный диск и ошибка rename без замены исходной базы.
- Реальные файловые операции и перенос закрытой тестовой папки с задачами, корзиной, заметками и предыдущей копией.
- Отображение режима, запрет автозапуска и открытие папки через имитацию desktop API в браузере.
- Русская и английская раскладка настроек при 1440/390 px и автоматические WCAG AA проверки.

Браузерная имитация IPC не подтверждает работу native shell или Windows Registry. Обычный запуск реального launcher с отдельным подключением к debug-портам завершился кодом 2147483651 до интерфейса: `install_dir_access.cc:52`, sandbox-процессы не могут читать распакованный каталог TEMP без разрешения ALL APPLICATION PACKAGES. Прямое подключение Playwright к NSIS launcher также не удалось использовать. ACL и sandbox не изменялись; нативное восстановление после переноса, штатный выход, съёмный носитель и USB disconnect остаются непроверенными. Извлечение носителя при работающем приложении может прервать запись; ошибки хранения и восстановление описаны в [STORAGE.md](STORAGE.md).

Реализация: `desktop/data-location.cjs`. Вызовы изменения `userData` и `sessionData` выполняются синхронно до ready; это соответствует [документации Electron app.setPath](https://www.electronjs.org/docs/latest/api/app#appsetpathname-path). Переменные wrapper проверены по установленному шаблону `app-builder-lib/templates/nsis/portable.nsi` версии 26.18.0.
